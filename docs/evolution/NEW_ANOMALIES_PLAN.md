# План новых аномалий (фаза C), составлен 2026-11-14 по составу карты v37

Источник: офлайн-список объектов `docs/evolution/list_names.py maps/Kontur_Office_v37.rbxl` (4 582 имени; 578 моделей, 3 437 деталей). Принцип: дёшево по нагрузке, меняется то, что уже стоит на карте (как `ArchiveArtSwap`/`ArchiveCalendarShift`: сервер двигает или перекрашивает существующие модели, ничего тяжёлого не добавляется). Не добавлять ассеты Roblox: звук только из уже используемых в проекте id (9125724963, 9117233449, 9117233311) или вообще без звука; новые звуки/модели требуют указания пользователя.

Подключение к раундам: `createOfficeObjects(office, state)` в `OfficeObjects.server.luau` возвращает `{activate, names}`; новые сценарии добавляются в `names` и обрабатываются в `activate(scenario, round)`. Новый слой пишется отдельным модулем в `sources/evolution-vNN/` и склеивается в сборке поверх самой свежей версии. Клиентской части у дешёвых аномалий нет: клиент рисует только то, что есть на карте.

## Порядок реализации
Сначала самые дешёвые и надёжные по объектам (#1, #2, #3, #10, #8, #6, #11), затем остальные. Каждая аномалия: серверная функция «применить/сбросить» (возврат исходного положения на следующий раунд, как у `calendarPose`), запись в `names`, QA-переключение `OfficeQANext`, проверка в Studio (до/после кадры с высоты глаз), ревью, строка в `OVERNIGHT_REPORT.md`. Раунды с несколькими новыми сценариями получают равные шансы; уровень 1 остаётся чистым.

## Риски
- Имена объектов выровнены без иерархии: перед реализацией сверять конкретные `V09_NNNN_<имя>` в Studio.
- Объекты внутри кабинок/шкафов могут быть заблокированы стримингом: аномалия должна проверяться на клиенте, не только на сервере.
- Подсчёт «лёгкая» оценён по аналогам (`ArchiveArtSwap`); реальную цену дадут замеры в Play.
